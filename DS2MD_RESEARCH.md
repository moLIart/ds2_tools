# You Are Empty: исследование формата DS2MD

## Статус и источники

Восстановлена структура стандартного бинарного DS2MD версий `0.9` и `1.0`: меши, материалы и текстурные слоты, привязки вершин к костям, объекты коллизии, скелет, анимации, события и группы контроллеров анимации.

Исходная точка — пользовательский шаблон ImHex, который извлекал меш из `svin.ds2md`. Результаты получены чтением реальных файлов моделей, разбором PE и дизассемблированием DLL через Capstone с ручным восстановлением логики. Это не исходники движка и не результат автоматической декомпиляции в C/C++. Имена полей ниже — исследовательские, если отдельно не указана привязка к строкам или именованным импортам движка.

Артефакты рядом с документом:

- [ds2md.hexpat](ds2md.hexpat) — шаблон ImHex для стандартного бинарного формата.
- [inspect_ds2md.py](inspect_ds2md.py) — проверочный парсер без сторонних Python-зависимостей; выводит метаданные, счётчики и смещения массивов. Это не экспортёр модели и не реализация skinning.

Модели, исполняемые файлы и существующие базы IDA `.i64` при исследовании не изменялись.

## Откуда известны версии 0.6 и 0.5

Они обнаружены непосредственно в заголовках моделей из установленного набора ресурсов. Это не предположение по расширению, времени файла или версии игры и не сведения из внешней статьи.

### Бинарный 0.6

Пример: [gameres/models/krovat.ds2md](../gameres/models/krovat.ds2md).

| Смещение | Байты | Интерпретация |
|---:|---|---|
| `0x00` | `0E 00` | Длина первой строки: 14 байт, little-endian `u16` |
| `0x02` | `44 53 32 4D 6F 64 65 6C 46 69 6C 65 5F 31` | `DS2ModelFile_1` |
| `0x10` | `03 00` | Длина строки версии: 3 байта |
| `0x12` | `30 2E 36` | `0.6` |

Таким образом, сигнатура и версия имеют тот же двоичный префикс «длина + байты строки», что и у современных образцов. Полная схема данных после этого префикса для `0.6` не восстановлена; переносить на неё описание `0.9`/`1.0` нельзя.

Все найденные бинарные файлы с этой версией:

```text
gameres/models/krovat.ds2md
gameres/models/medscen1.ds2md
gameres/models/medscen2.ds2md
gameres/models/toilet.ds2md
gameres/models/trash_box.ds2md
```

### Текстовый 0.5

## Базовые типы бинарного формата 0.9 / 1.0

- Все многобайтовые значения — little-endian.
- `float` — 32-битное значение IEEE 754.
- Поля записаны плотно, без выравнивающего padding между ними.
- `String` — `u16 byte_length`, затем ровно `byte_length` байт; завершающего NUL в файле нет.
- Кодировка строк в файле не помечена. Python-парсер использует CP1251 для отображения; это выбор инструмента, не доказанная гарантия формата.
- `Float2`, `Float3`, `Quaternion` — соответственно 2, 3 и 4 последовательных `float`.
- `Matrix4` — 16 последовательных `float`, 64 байта. Загрузчик `0x10058780` читает их и транспонирует в памяти; массивы, выданные Python-парсером, оставлены в порядке файла.

Псевдокод ниже описывает порядок сериализации, а не ABI-структуры C/C++ в памяти процесса.

## Верхний уровень модели

```text
String file_id                 // "DS2ModelFile_1"
String version                 // "0.9" или "1.0"
String name
u8 mesh_count
Mesh meshes[mesh_count]
u8 collision_object_count
CollisionObject collision_objects[collision_object_count]
u8 has_skeleton
if has_skeleton != 0:
    Skeleton skeleton
```

Если скелета нет, чтение заканчивается после `has_skeleton`. Все корни, анимации, группы и финальный счётчик слотов находятся внутри условного блока скелета.

Главный загрузчик — `0x100BC320`. Проверка сигнатуры — около `0x100BC47A`; сравнения версий — `0x100BC4FE` и `0x100BC527`.

## Меш

Конструктор-диспетчер `0x100C3B30` вызывает стандартный reader `0x100C2D60`, когда последний аргумент равен нулю. Главный загрузчик модели передаёт именно ноль. Версия модели в reader меша не передаётся: у исследованных `0.9` и `1.0` используется одна схема меша.

### Порядок полей

| Поле | Представление | Смысл |
|---|---|---|
| `material` | `String` | Имя материала / shader descriptor |
| `diffuse_texture` | `String` | Diffuse-слот |
| `bump_texture` | `String` | Bump/normal-слот; Lua override называет его `normalmap` |
| `luminosity_texture` | `String` | Luminosity-слот |
| `reflection_texture` | `String` | Reflection-слот |
| `specular_texture` | `String` | Specular-слот, именно последняя текстурная строка |
| `header` | 33 байта | Поля в следующем подразделе |
| `index_count` | `u32` | Число индексов, не число треугольников |
| `indices` | `u16[index_count]` | Индексы вершин |
| `vertex_count` | `u16` | Число вершин |
| `positions` | `Float3[vertex_count]` | Позиции |
| `normals` | `Float3[vertex_count]` | Нормали |
| `uv_coords` | `Float2[vertex_count]` | Текстурные координаты |
| `influence_mode` | `u8` | При нуле массив привязок отсутствует |
| `assignments` | `VertexAssignment[vertex_count]`, только при ненулевом `influence_mode` | Влияния костей |

Имена текстурных слотов подтверждены lookup-кодом `0x100A2BF0` и строками `$diffuse$`, `$bump$`, `$luminosity`, `$reflection$`, `$specular$`, а не только содержимым моделей. Порядок чтения строк — `0x100C2D9E–0x100C2ECC`.

Позиции, нормали и UV читаются безусловно. В стандартном reader нет дополнительных UV-наборов или массивов vertex colors.

### 33 байта после строк

Смещение в таблице относительно конца шестой строки:

| Смещение | Тип | Поле | Основание |
|---:|---|---|---|
| `+0` | `Float3` | `bounds_min` | Чтение `0x100C2F59` |
| `+12` | `Float3` | `bounds_max` | Чтение `0x100C2F7C` |
| `+24` | `u32` | `primitive_count` | Чтение `0x100C2F9F` |
| `+28` | `u8` | `triangle_strip` | Чтение `0x100C2FB4` |
| `+29` | `u32` | `skinning_count` | Чтение `0x100C2FD4` |

AABB подтверждён потребителем: `0x100BC61E–0x100BC6B4` покомпонентно объединяет границы мешей в границы модели.

`triangle_strip == 0` означает triangle list; любое ненулевое значение — triangle strip. Код отрисовки `0x100C48B6–0x100C48E1` выбирает соответственно OpenGL primitive `4` или `5`.

`primitive_count` используется как число треугольников в list-пути. Точная зависимость от числа индексов для strip-пути отдельно не установлена; нельзя без проверки подставлять `index_count / 3` для любого меша.

`skinning_count` управляет путями движка:

- `0` — без skinning;
- `1` — rigid-оптимизация с одной костью;
- `>1` — skinned-путь; это значение также участвует в проверке пригодности для GPU-skinning.

Во всех 976 мешах с влияниями поле совпало с числом уникальных индексов костей в привязках. Это сильное эмпирическое подтверждение значения «число используемых костей», но исходное имя поля неизвестно, поэтому в артефактах сохранено нейтральное имя.

### Привязка вершины

```text
VertexAssignment:
    u8 bone_count
    repeat bone_count times:
        u16 bone_index
        float weight
```

Байт `influence_mode` читается в `0x100C31D4`; проверка нуля — `0x100C3203`. При ненулевом значении читается отдельный `bone_count` каждой вершины, даже если `influence_mode == 1`.

Диагностическая строка движка называет `influence_mode` числом bone influences. Во всех проверенных мешах с привязками он совпал с максимальным `bone_count` среди вершин. Значение `bone_count >= 10` отвергается движком в `0x100C32C4`.

## Объекты коллизии

Это блок, который в исходном пользовательском шаблоне назывался `ds2_skeleton`.

```text
CollisionObject:
    String name
    u8 type
    u16 bone_index             // FFFF: нет привязки к кости
    Matrix4 local_matrix
    параметры по type
```

| `type` | Примитив | Параметры после матрицы | Размер параметров, байт |
|---:|---|---|---:|
| `0` | Sphere | `float radius` | 4 |
| `1` | Box | `Float3 lengths`, полные длины сторон | 12 |
| `2` | Cylinder, не capsule | `float radius`, `float length` | 8 |
| `3` | Dummy / именованная трансформация | Нет | 0 |
| Другие значения | Семантика не установлена | Текущий reader также не читает параметры | 0 |

Стандартный reader — `0x100B6EA0`. Смысл типов подтверждён вызовами именованных импортов `ODE::Shape::AddSphere`, `AddBox`, `AddCylinder` в `gameres/executables/sv_game.dll:0x1007B404–0x1007B4A2`.

У коробки записаны полные размеры: вычисление её радиуса использует половину максимального размера. Dummy-объекты встречаются, например, под именами `#Dummy` и `#hinge`. Чтение даже одного лишнего `float` после dummy сдвигает весь остаток файла.

## Скелет

Reader — `0x100CD2C0`, вызывается через конструктор `0x100CE310`.

```text
Skeleton:
    u16 bone_count
    Bone bones[bone_count]
    u16 root_count
    u16 root_indices[root_count]
    u16 animation_count
    Animation animations[animation_count]
    u16 group_count
    AnimationGroup groups[group_count]
    u16 animation_slot_count
```

### Кость

```text
Bone:
    String name
    Matrix4 local_rest_matrix
    u16 parent_index           // FFFF: корень
    u16 child_count
    u16 child_indices[child_count]
    u16 animation_slot_index
```

Reader — `0x100CCD30`. Локальный характер rest-матрицы подтверждается вычислением накопленной трансформации через родителя в `0x100CB23F–0x100CB277`.

Последнее слово кости — индекс слота контроллера анимации, не material/shader slot. Оно попадает в поле объекта кости `+0xCE`. Код `0x100D9096–0x100D90A7` использует его для индексации массива указателей на контроллеры. Размер массива задаёт последнее `animation_slot_count` всего скелета.

## Анимации

### Заголовок и каналы

```text
Animation:
    String name
    float duration_seconds
    float time_parameter_seconds
    u16 channel_count
    AnimationChannel channels[channel_count]
    if model.version == "1.0":
        u16 event_count
        AnimationEvent events[event_count]

AnimationChannel:
    u16 bone_index
    String bone_name
    u32 key_count
    AnimationKey keys[key_count]
```

Reader анимации — `0x100D1370`. `duration_seconds` подтверждён потребителями длительности. Второй `float` точно является временным параметром: движок умножает его на 1000, как и длительность, при переводе в миллисекунды. Значение «интервал семплирования» — гипотеза, поэтому оно не закреплено в имени поля.

### Ключ: 45 байт

Reader — `0x100CF790–0x100CF8EE`.

| Смещение в ключе | Размер, байт | Поле |
|---:|---:|---|
| `+0` | 1 | `u8 flags` |
| `+1` | 16 | Quaternion `x, y, z, w`, четыре `float` |
| `+17` | 12 | `Float3 translation` |
| `+29` | 12 | `Float3 scale` |
| `+41` | 4 | `float time_seconds` |

Quaternion нормализуется при загрузке. Reader канала проверяет строгое возрастание времён ключей (`0x100D0FEF–0x100D1022`).

Между двумя различными ключами режим интерполяции определяется флагами правого, то есть следующего по времени, ключа:

| Маска | Поведение | Адрес потребителя |
|---:|---|---|
| `0x01` | Удерживать вращение левого ключа; иначе slerp | `0x100D2B4D` |
| `0x02` | Удерживать перенос левого ключа; иначе lerp | `0x100D2C8C` |
| `0x04` | Удерживать масштаб левого ключа; иначе lerp | `0x100D2D11` |
| `0x08` | Включить использование масштаба | `0x100D2CFA` |

Внутри интервала отключённый `0x08` правого ключа даёт единичный масштаб. При `0x08 | 0x04` удерживается масштаб слева, причём применение удержанного масштаба зависит от `0x08` левого ключа. В точный момент ключа используются его собственные значения и бит масштаба.

Матрица локальной анимационной позы имеет порядок `T * S * R` для векторов-столбцов: неравномерный масштаб умножает строки матрицы вращения. Это видно в `0x100D49B8–0x100D4AC5` и последующем умножении `0x100D4AC7` и далее. Обычное `T * R * S` здесь дало бы другой результат.

Старшие биты пока не расшифрованы. Они не меняют размер записи.

### События: различие 0.9 и 1.0

Проверка `strcmp(version, "1.0")` находится в `0x100D145D–0x100D1479`. В `0.9` нет ни массива событий, ни его счётчика; читать после каналов безусловный `u16` нельзя.

```text
AnimationEvent:
    float time_seconds
    String name
```

Запись события читается в `0x100D14B0–0x100D14EC`.

Пример реальных данных: в `gameres/models/actors/moto.ds2md`, анимация `walk`, счётчик событий расположен по `0x389AA`; записи содержат `(0.53333336, "step1")` и `(1.1333333, "step2")`.

### Группы контроллеров

```text
AnimationGroup:
    String name
    u16 bone_count
    u16 bone_indices[bone_count]
    u16 animation_slot_count
    u16 animation_slot_indices[animation_slot_count]
```

Reader — `0x100CD0E0–0x100CD1C2`. Вторая последовательность — индексы слотов контроллеров, а не ещё один список костей. Код `0x100D83F8–0x100D841D` присваивает контроллер группы каждому перечисленному слоту.

## Контрольный пример: svin.ds2md

Путь: [gameres/models/actors/svin.ds2md](../gameres/models/actors/svin.ds2md). Версия `1.0`, имя модели `Object01`, материал `model_actor`. SHA-256: `f03993dac2ef8498032f270bfb9be01cd37c929430e7595679a2e5c0d0d24264`.

| Блок | Смещение от начала файла | Содержимое |
|---|---:|---|
| Начало меша, первая строка материала | `0x20` | Один меш |
| Заголовок меша | `0x84` | AABB; 670 примитивов; list; `skinning_count = 2` |
| Счётчик индексов | `0xA5` | 2010 |
| Индексы | `0xA9` | `u16[2010]` |
| Счётчик вершин | `0x105D` | 599 |
| Позиции | `0x105F` | `Float3[599]` |
| Нормали | `0x2C73` | `Float3[599]` |
| UV | `0x4887` | `Float2[599]` |
| `influence_mode` | `0x5B3F` | 2 |
| Конец меша / счётчик коллизий | `0x6BE3` | Одна коллизия |
| Коллизия | `0x6BE4` | `#Box02`, box, привязка к кости 0 |
| `has_skeleton` | `0x6C3B` | 1 |
| Начало скелета / счётчик костей | `0x6C3C` | Две кости |
| Счётчик анимаций | `0x6CE0` | Шесть анимаций |
| Первая анимация | `0x6CE2` | `run` |
| Счётчик групп | `0x8C08` | Три группы |
| Общее число слотов | `0x8C48` | 1 |
| EOF | `0x8C4A` | Полный размер 35914 байт |

В привязках 588 вершин имеют одно влияние, 11 — два. Кости: `Bone01` — корень; `Bone02` — его ребёнок. Обе используют слот контроллера 0. Анимации: `run`, `jamp1`, `jamp2`, `jamp3`, `jamp4`, `idle`; написание `jamp` взято из файла. Группы `entry_model`, `upper_model`, `nogi` содержат кости `[0, 1]` и слоты `[0]`.

Границы записанных позиций не совпадают с AABB меша. После применения восстановленной цепочки `animated_global * inverse(global_bind)` к `run` при `t=0` границы совпадают с AABB с погрешностью порядка `1e-5`. Записанные позиции нельзя просто домножать на локальные матрицы костей.

Неразрешённые ссылки имеют семь различных имён файлов: `PePe_2.tga`, `Weapon_PPSH_magazin.tga`, `Mauz.tga`, `vod-4a-1.jpg`, `barja01.tga`, `barja02.tga`, `pimpa.tga`. Исходных полных строк восемь, поскольку `Mauz.tga` указан с разными префиксами.

Шейдер использует RGB альбедо вместе с существующим простым освещением; цвет палитры не подкрашивает найденную текстуру. Текстурные координаты повторяются за пределами `[0, 1]` (`GL_REPEAT`). Готовые mip-уровни DDS загружаются без пересжатия; для TGA цепочка генерируется через `glGenerateMipmap`. Уменьшение использует трилинейную фильтрацию `GL_LINEAR_MIPMAP_LINEAR`, увеличение — `GL_LINEAR`. У DDS без mip-уровней используется только базовое изображение, а неполная цепочка ограничивается последним сохранённым уровнем через `GL_TEXTURE_MAX_LEVEL`. Прозрачность, normal/bump, specular, reflection и luminosity не воспроизводятся.

Для текстур также задаётся максимальная доступная анизотропия (`GL_MAX_TEXTURE_MAX_ANISOTROPY`) поверх mip-фильтрации. Требуется OpenGL 4.6 либо расширение ARB/EXT texture_filter_anisotropic; при отсутствии поддержки выводится предупреждение и остаётся трилинейная фильтрация.

Координата V в исследованном меше записки равна 0 у верхних вершин и 1 у нижних. DDS-декодер pyglet загружает сжатые блоки без переворота, поэтому для DDS используются исходные UV. Pillow-декодер TGA переворачивает изображение в нижнее начало OpenGL; для TGA шейдер компенсирует это через `1 - V`.

При добавлении альбедо без запуска интерфейса проверены разрешение реальных ссылок, чтение DDS/TGA и выборка пикселей в невидимом графическом контексте. На `sv.dds`, `masha.dds` и `telephone_01..tga` выборка сопоставлена с декодированными пикселями файлов, включая ориентацию V. При последующей проверке анимации текстурированные модели также отрисованы в реальном окне.

### Анимация, координаты и ограничения

[ds2md_animation.py](ds2md_animation.py) загружает метаданные скелета, вычисляет inverse bind один раз и декодирует ключи только выбранного клипа. При открытии автоматически проигрывается первый клип; модель без клипов остаётся статичной. Переключение на bind pose останавливает проигрывание.

Внутренние CPU-матрицы row-major действуют на векторы-столбцы. Матрицы файла транспонируются. Глобальная bind-матрица `B_i = B_parent * local_rest_i`, глобальная текущая поза `G_i(t) = G_parent(t) * local_pose_i(t)`, итоговая матрица `S_i(t) = G_i(t) * inverse(B_i)`. Анимационный канал заменяет локальную исходную матрицу; при отсутствии канала сохраняется `local_rest_i`. Вращение интерполируется по кратчайшей дуге slerp, перенос и масштаб — lerp с флагами правого ключа. Используются времена ключей, а не предположительный FPS из второго параметра.

Цепочка подтверждена в `ds2render.dll`: `0x100CABF0` накапливает исходные матрицы через родителей; `0x100CD657–0x100CDC9C` обращает накопленные матрицы; `0x100D48C0` вычисляет анимированную иерархию; `0x100D7C00` и далее строит палитру skinning.

На CPU каждый кадр вычисляются только матрицы костей. Позиции и нормали деформируются в вершинном GLSL 3.3-шейдере; UV и альбедо сохраняются. Все влияния вершины читаются из `RG32F`-текстуры, column-major палитра матриц — из `RGBA32F`-текстуры через `texelFetch`. Двумерные float-текстуры выбраны потому, что pyglet 2.1.19 не распознаёт uniform типа `samplerBuffer`. Веса сохраняются без нормализации или обрезания до двух/четырёх; в корпусе встречаются шесть влияний, reader движка допускает до девяти. Вершины без влияний остаются в исходных координатах.

Камера вписывается по консервативным границам текущей позы, а не по записанному AABB. AABB исходных вершин для каждой влияющей кости готовятся при загрузке; при смене позы преобразуются их углы с учётом диапазона сумм весов. Вписывание происходит при открытии, выборе клипа и `F`, но не каждый кадр или при перемотке. Область 3D отделена от заголовка и нижних элементов управления, включая размер окна `640x420`.

Начальный ракурс и вписывание используют азимут `125°` вместо прежних `-55°`, при прежнем подъёме `20°`: камера перенесена на противоположную сторону модели в плоскости XY, без изменения высоты, расстояния и точки взгляда. Это единый ракурс при открытии, выборе клипа и `F`, а не автоматическое определение лица: исходная ориентация моделей различается. В реальном окне проверены `svin`, смена на `ded0` после вращения и сброс через `F`; у `svin` новый ракурс показывает переднюю сторону, у `ded0` — спину.

#### Исправление z-fighting при приближении

Исходная проекция использовала `near` порядка `radius * 1e-4`, а при попадании камеры внутрь консервативной сферы — вплоть до `radius * 1e-6`. На `moto` при неизменной дистанции камеры границы анимационной позы переключали `near` между примерно `0.0094` и `0.000096`. Отношение `far / near` доходило до `1e7` при фактическом 24-битном depth buffer. Это меняло квантование глубины между кадрами и давало мерцание при движении, а не ошибку skinning.

`_clip_planes` в [view_ds2md.py](view_ds2md.py) теперь проецирует AABB текущей позы и видимой сетки на направление взгляда. Near/far охватывают нужный диапазон глубины с запасом; снизу `near` ограничен одним процентом текущей орбитальной дистанции, а не почти нулевым порогом сферы. Переход камеры внутрь границ больше не вызывает стократного скачка. Границы сетки сохраняются при загрузке, поэтому уточнение `far` не обрезает её дальнюю часть.

Исправление проверено при непрерывном проигрывании, вращении и приближении камеры: 349 отрисованных кадров `moto` и 351 кадр `ded0`, без ошибок OpenGL и без межкадровых скачков `near` более чем в десять раз. В этих прогонах максимальное `far / near` меньше 1300. Статичные скриншоты не использовались как доказательство устранения временного мерцания. [test_ds2md_camera.py](test_ds2md_camera.py) проверяет шесть случаев: внешнюю камеру, вход в анимированные границы, прежний порог сферы, косой взгляд, геометрию позади камеры и разные единицы модели.

Это проигрывание одного клипа с базовым альбедо, а не полный игровой рендерер. Смешивание клипов и контроллеры групп не исполняются; события читаются как метаданные, но не запускают игровой код или звук. Normal/bump, specular, reflection, luminosity, прозрачность и физика не воспроизводятся.

Загрузчик сцены использует существующий `parse_model`, а не вторую реализацию полного формата. Он не подменяет некорректные координаты и не выдумывает геометрию для файлов без треугольников. Его проверка на исследованном корпусе дала:

| Результат подготовки геометрии | Число файлов |
|---|---:|
| Геометрия подготовлена | 1259 |
| Отклонены нечисловые или бесконечные позиции | 4 |
| Нет треугольников для отображения | 4 |
| Неподдерживаемые версии `0.5` / `0.6` | 23 |

Это отдельная проверка пригодности к отрисовке: успешная разметка файла до EOF не гарантирует конечные координаты или наличие треугольников. В частности, ранее установленные результаты структурного разбора остаются в силе.

Остальные восемь клипов относятся к моделям, отклонённым по геометрии. Новых отказов загрузки нет. `test_ds2md_animation.py` содержит 12 изолированных регрессий: иерархия и inverse bind, порядок неравномерного масштаба, граничные моменты ключей, флаги правого ключа, кватернионы, отсутствие каналов, перемотка, пауза, скорость и повтор.


В реальном окне проверены `svin`, `moto`, `ded0`, rigid-модель `animobj_test` и статическая `beriyastul`, размеры `1200x800` и `640x420`, управление воспроизведением, сохранение камеры при перемотке, остановка часов на паузе, смена моделей и сохранение предыдущей сцены после ошибки открытия. Transform feedback производственного вершинного шейдера сопоставлен с CPU-расчётом на всех вершинах `svin`, `moto` и `ded0`; максимальное абсолютное расхождение меньше `0.000022`. Отдельная GPU-проба с шестью равными весами подтверждает, что пятое и шестое влияния не отбрасываются. Ошибок OpenGL в этих проверках нет.

## Упаковка просмотрщика для отправки

[package_viewer.py](package_viewer.py) собирает ZIP только с исходным кодом просмотрщика и списком зависимостей. Он использует стандартную библиотеку Python и не запускает просмотрщик.

```powershell
python ds2_research/package_viewer.py
```

Результат — [dist/ds2md-viewer.zip](dist/ds2md-viewer.zip). Повторный запуск заменяет этот архив новой сборкой. При необходимости можно указать другой ZIP через `--output viewer.zip`.

Внутри папки `ds2md_viewer/ds2_research` находятся ровно пять файлов: `view_ds2md.py`, `ds2md_scene.py`, `ds2md_animation.py`, `inspect_ds2md.py`, `requirements-viewer.txt`. Список задан явно: модели, текстуры, DLL игры, базы IDA, документы исследования, тесты, `__pycache__`, сам упаковщик и установленные сторонние пакеты не включаются.

Получателю нужны Python 3.11+ и подходящий OpenGL-драйвер. После распаковки перейти в папку `ds2md_viewer` и выполнить:

```powershell
python -m pip install -r ds2_research/requirements-viewer.txt
python ds2_research/view_ds2md.py
```

Это архив Python-кода, не самостоятельный EXE и не комплект игры. Модели получатель выбирает из собственных локальных файлов. Для отображения альбедо его локальные текстуры должны быть в `gameres/textures` рядом с папкой `ds2_research`; без них модель откроется с однотонным материалом и предупреждением.

Обновлённый упаковщик проверен на временном ZIP: точный состав из пяти файлов, CRC, распаковка, запуск `view_ds2md.py --help` вне каталога игры и загрузка `svin/run` распакованными модулями с вычислением позы при `t=0.1`. Временный архив удалён. Окно распакованной копии отдельно не запускалось; GUI-проверки выше относятся к исходникам репозитория.

## Что остаётся неустановленным

- Полные схемы текстового `0.5` и бинарного `0.6`, их загрузчики и конвертеры.
- Точное назначение второго временного параметра анимации.
- Старшие биты флагов ключа.
- Точная связь `primitive_count` и количества индексов у strips.
- Полная семантика packed/cache-формата `.ds2md.of`. У него есть отдельный reader; это не просто версия `0.9` или `1.0`, и описанный здесь стандартный layout к нему неприменим.

Ни одно из этих неизвестных полей не мешает установленной разметке стандартных бинарных моделей исследованного корпуса.
