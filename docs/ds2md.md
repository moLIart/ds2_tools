# You Are Empty: исследование формата DS2MD

## Статус и источники

Восстановлена структура стандартного бинарного DS2MD версий `0.9` и `1.0`: меши, материалы и текстурные слоты, привязки вершин к костям, объекты коллизии, скелет, анимации, события и группы контроллеров анимации.

Дополнительно исследованы текстовый `0.5` и бинарный `0.6`: ниже приведены полный список файлов и восстановленный порядок данных.

Результаты получены чтением реальных файлов моделей, разбором PE и дизассемблированием DLL с ручным восстановлением логики. Это не исходники движка и не результат автоматической декомпиляции в C/C++. Имена полей ниже — исследовательские, если отдельно не указана привязка к строкам или именованным импортам движка.

## Другие представления моделей: список и структура

Повторная инвентаризация всех файлов `*.ds2md` под `gameres` дала 1290 моделей. Вне бинарных `0.9`/`1.0` находятся пять бинарных `0.6` и 18 текстовых `0.5`. Неопознанных заголовков в этой выборке нет. Классификация основана на содержимом заголовка, а не на имени файла, времени изменения или версии игры.

### Бинарный 0.6

Пример: `gameres/models/krovat.ds2md` (файл игры в репозиторий не входит).

| Смещение | Байты | Интерпретация |
|---:|---|---|
| `0x00` | `0E 00` | Длина первой строки: 14 байт, little-endian `u16` |
| `0x02` | `44 53 32 4D 6F 64 65 6C 46 69 6C 65 5F 31` | `DS2ModelFile_1` |
| `0x10` | `03 00` | Длина строки версии: 3 байта |
| `0x12` | `30 2E 36` | `0.6` |

Сигнатура и версия имеют тот же двоичный префикс «длина + байты строки», что и у современных образцов, но остальной layout отличается. В частности, здесь есть имя каждого меша, interleaved-вершины перед индексами и собственная матричная анимация; переносить описание `0.9`/`1.0` нельзя.

Все найденные бинарные файлы с этой версией:

```text
gameres/models/krovat.ds2md
gameres/models/medscen1.ds2md
gameres/models/medscen2.ds2md
gameres/models/toilet.ds2md
gameres/models/trash_box.ds2md
```

#### Наблюдаемая схема бинарного 0.6

Все многобайтовые значения little-endian, поля упакованы без выравнивания. `String` — `u16` длины и указанное число байтов, без NUL; вершина — восемь `f32`: позиция XYZ, нормаль XYZ, UV. `AABB` — минимум XYZ и максимум XYZ; матрица — 16 `f32` в порядке файла.

```text
String magic = "DS2ModelFile_1"
String version = "0.6"
f32 header_parameter                 // 0x15: 1.0 или 30.0
u16 mesh_count                       // 0x19
repeat mesh_count:
    String mesh_name, material, textures[5]
    u32 triangle_count, vertex_count, index_count
    u8 unknown_before_vertices       // во всех шести мешах 0
    Vertex vertices[vertex_count]    // 32 байта на вершину
    u16 indices[index_count]
    u32 sample_count                 // F
    u8 mode
    AABB bounds[max(1, F)]
    if mode == 1:
        u16 track_count              // K
        repeat K:                    // сначала целиком один трек
            Matrix pre_matrix
            Matrix samples[F]
        u32 assignment_count
        repeat assignment_count:
            u8 influence_count
            repeat influence_count:
                u16 track_index
                f32 weight
    if mode == 2:
        Matrix samples[F]
    if mode == 3:
        // дополнительных полей меша нет
u16 collision_count
repeat collision_count:              // в корпусе только type == 1
    String name
    u8 type
    byte opaque[8]
    f32 parameters[3]
    Matrix matrix
EOF
```

Схема потребляет все пять файлов до точного EOF: 6 мешей, 11130 вершин, 40140 индексов / 13380 треугольников. Координаты, нормали и UV конечны, индексы находятся в границах массива вершин; во всех мешах `index_count == 3 * triangle_count`.

| Файл относительно `gameres/models` | Размер, байт | Мешей | Вершин | Индексов | F / mode | Коллизий |
|---|---:|---:|---:|---:|---|---:|
| `krovat.ds2md` | 36326 | 1 | 976 | 2316 | `0 / 3` | 3 |
| `medscen1.ds2md` | 1139210 | 2 | 4885 | 17844 | `260 / 1`, `260 / 2` | 0 |
| `medscen2.ds2md` | 137271 | 1 | 3365 | 14706 | `0 / 3` | 0 |
| `toilet.ds2md` | 36416 | 1 | 932 | 3114 | `0 / 3` | 2 |
| `trash_box.ds2md` | 36049 | 1 | 972 | 2160 | `0 / 3` | 5 |

Режим `3` статичный, `2` содержит матрицы целого меша, `1` — матричные треки и взвешенные ссылки вершин на них. В `medscen1` меш `protivogaz` имеет 53 трека, по одной предварительной матрице и 260 матриц отсчётов в каждом: всего 13833 матрицы. Массив привязок содержит 3365 записей: 1876 вершин с одним влиянием, 1489 с двумя; номера треков `0..52`. Второй меш `pistol` содержит 260 матриц без весов.

Порядок преобразований подтверждён расчётом границ. Для row-vector записи матриц файла сначала применяется `pre_matrix[k]`, затем `samples[k][frame]`; результаты суммируются с весами вершины. На кадрах `0`, `1`, `130`, `259` максимальное расхождение с записанными AABB меньше `3.6e-5`; для rigid-меша — меньше `1.5e-5`. Обратный порядок матриц и применение только одного из двух множителей границы не воспроизводят. Это матричные отсчёты, а не современный список именованных костей и quaternion-ключей.

Контрольные смещения `medscen1`: геометрия первого меша начинается в `0x94`, индексы — `0x1A534`, `F/mode` — `0x21818`, AABB — `0x2181D`, число треков — `0x2307D`, матрицы — `0x2307F`, число привязок — `0xFB2BF`, следующий меш — `0x1031AC`. Финальный `u16 collision_count == 0` расположен в `0x116208`, EOF — `0x11620A`.

В десяти старых коллизиях `type == 1`, непрозрачные восемь байтов равны `CC CC CC CC CC CC CC CC`, после них идут три положительных параметра и матрица. Это не современный порядок `bone_index + matrix + parameters`; байты `CC` нельзя трактовать как номер кости. Отдельного современного `has_skeleton` после коллизий в этих файлах нет.

Не установлены: точный смысл `header_parameter` (частота отсчётов — гипотеза), назначение восьми байтов коллизии и нулевого байта перед вершинами, другие типы коллизии и режимы анимации. Иерархия и имена треков в восстановленном потоке не обнаружены.

### Текстовый 0.5

Пример: `gameres/models/sky/sky_333.ds2md` (файл игры в репозиторий не входит). Первые две строки файла буквально содержат:

```text
"DS2ModelFile_1"
"0.5"
```

Вместо двоичных длин здесь кавычки и переводы строк CRLF; дальше следуют текстовые имена и числовые данные. Строка `0.5` проверена во всех обнаруженных текстовых образцах, а не выведена только по первому файлу.

#### Наблюдаемая схема текстового 0.5

Файл — поток токенов, а не строки фиксированного назначения. Строки заключены в кавычки, числа записаны десятичным текстом; пробелы, табуляция и CRLF разделяют токены. Следующее имя меша может находиться в конце предыдущей числовой строки. Обратные слеши внутри кавычек буквальные: пути вроде `"Y:\INDUSTRY\mtl_plate_03.tga"` и UNC-пути нельзя обрабатывать как escape-последовательности. Экранированные кавычки в выборке не встречены.

Ниже `Int` / `Real` — типы текстовых токенов, не доказательство двоичной разрядности:

```text
String magic = "DS2ModelFile_1"
String version = "0.5"
Int mesh_count
repeat mesh_count:
    String mesh_name, material, textures[5]
    Int triangle_count, vertex_count, index_count, unknown_A
    repeat vertex_count:
        Real position[3], normal[3], uv[2]
    Int indices[index_count]
    Int sample_count                  // F
    Real rate_parameter
    AABB bounds[max(1, F)]             // по шесть Real
    Int unknown_B
    Int has_matrices
    if has_matrices == 1:
        Matrix samples[F]             // по 16 Real
    Int unknown_C
Int terminal
whitespace
EOF
```

Все 18 файлов разобраны до точного EOF: 923829 байт, 157850 токенов, 120 мешей, 11635 вершин, 55476 индексов / 18492 треугольника. Геометрические числа конечны, индексы корректны, везде `index_count == 3 * triangle_count`. Все `unknown_A/B/C` и `terminal` равны нулю; их ненулевые ветки и смысл пока не установлены.

В 17 моделях неба 117 статичных мешей: `F == 0`, одна AABB, `has_matrices == 0`. Записанные AABB точно совпадают с экстремумами сериализованных позиций. Есть и плоские skybox-меши, и сферические меши; это не один повторяющийся четырёхвершинный пример. `rate_parameter` равен `1` у кубических вариантов и `30` у сферических.

`vent.ds2md` содержит три меша `$Propeller`: соответственно 180 / 773 / 40 вершин и 480 / 1998 / 90 индексов. У каждого `F == 100`, параметр `30`, сто AABB и сто матриц (`has_matrices == 1`). Применение каждой матрицы к позициям соответствующего меша воспроизводит AABB с максимальным расхождением меньше `0.0012`, что согласуется с округлением текстовых чисел. Перенос находится в элементах `12..14` матрицы файла; это наблюдаемая rigid-анимация мешей, не обнаруженный скелет с весами. Случай `has_matrices == 1` при `F == 0` в корпусе отсутствует.

Контрольные байтовые смещения первого меша `sky_77`: имя — `27`, счётчики — `139`, вершины — `147`, индексы — `359`, `F/rate` — `371`, AABB — `382`. Это смещения в конкретном текстовом файле, не фиксированные адреса полей всего формата.

## Базовые типы бинарного формата 0.9 / 1.0

- Все многобайтовые значения — little-endian.
- `float` — 32-битное значение IEEE 754.
- Поля записаны плотно, без выравнивающего padding между ними.
- `String` — `u16 byte_length`, затем ровно `byte_length` байт; завершающего NUL в файле нет.
- Кодировка строк в файле не помечена.
- `Float2`, `Float3`, `Quaternion` — соответственно 2, 3 и 4 последовательных `float`.
- `Matrix4` — 16 последовательных `float`, 64 байта. Загрузчик `0x10058780` читает их и транспонирует в памяти; порядок значений в файле при этом не меняется.

Псевдокод ниже описывает порядок сериализации, а не ABI-структуры C/C++ в памяти процесса.

## Верхний уровень модели

```text
String file_id                 // "DS2ModelFile_1"
String version                 // "0.9" или "1.0"
String name
u8 mesh_count
Mesh meshes[mesh_count]
u8 collision_object_count
CollisionObject collision_objects[collision_object_count]
u8 has_skeleton
if has_skeleton != 0:
    Skeleton skeleton
```

Если скелета нет, чтение заканчивается после `has_skeleton`. Все корни, анимации, группы и финальный счётчик слотов находятся внутри условного блока скелета.

Главный загрузчик — `0x100BC320`. Проверка сигнатуры — около `0x100BC47A`; сравнения версий — `0x100BC4FE` и `0x100BC527`.

## Меш

Конструктор-диспетчер `0x100C3B30` вызывает стандартный reader `0x100C2D60`, когда последний аргумент равен нулю. Главный загрузчик модели передаёт именно ноль. Версия модели в reader меша не передаётся: у исследованных `0.9` и `1.0` используется одна схема меша.

### Порядок полей

| Поле | Представление | Смысл |
|---|---|---|
| `material` | `String` | Имя материала / shader descriptor |
| `diffuse_texture` | `String` | Diffuse-слот |
| `bump_texture` | `String` | Bump/normal-слот; Lua override называет его `normalmap` |
| `luminosity_texture` | `String` | Luminosity-слот |
| `reflection_texture` | `String` | Reflection-слот |
| `specular_texture` | `String` | Specular-слот, именно последняя текстурная строка |
| `header` | 33 байта | Поля в следующем подразделе |
| `index_count` | `u32` | Число индексов, не число треугольников |
| `indices` | `u16[index_count]` | Индексы вершин |
| `vertex_count` | `u16` | Число вершин |
| `positions` | `Float3[vertex_count]` | Позиции |
| `normals` | `Float3[vertex_count]` | Нормали |
| `uv_coords` | `Float2[vertex_count]` | Текстурные координаты |
| `influence_mode` | `u8` | При нуле массив привязок отсутствует |
| `assignments` | `VertexAssignment[vertex_count]`, только при ненулевом `influence_mode` | Влияния костей |

Имена текстурных слотов подтверждены lookup-кодом `0x100A2BF0` и строками `$diffuse$`, `$bump$`, `$luminosity`, `$reflection$`, `$specular$`, а не только содержимым моделей. Порядок чтения строк — `0x100C2D9E–0x100C2ECC`.

Позиции, нормали и UV читаются безусловно. В стандартном reader нет дополнительных UV-наборов или массивов vertex colors.

### 33 байта после строк

Смещение в таблице относительно конца шестой строки:

| Смещение | Тип | Поле | Основание |
|---:|---|---|---|
| `+0` | `Float3` | `bounds_min` | Чтение `0x100C2F59` |
| `+12` | `Float3` | `bounds_max` | Чтение `0x100C2F7C` |
| `+24` | `u32` | `primitive_count` | Чтение `0x100C2F9F` |
| `+28` | `u8` | `triangle_strip` | Чтение `0x100C2FB4` |
| `+29` | `u32` | `skinning_count` | Чтение `0x100C2FD4` |

AABB подтверждён потребителем: `0x100BC61E–0x100BC6B4` покомпонентно объединяет границы мешей в границы модели.

`triangle_strip == 0` означает triangle list; любое ненулевое значение — triangle strip. Код отрисовки `0x100C48B6–0x100C48E1` выбирает соответственно OpenGL primitive `4` или `5`.

`primitive_count` используется как число треугольников в list-пути. Точная зависимость от числа индексов для strip-пути отдельно не установлена; нельзя без проверки подставлять `index_count / 3` для любого меша.

`skinning_count` управляет путями движка:

- `0` — без skinning;
- `1` — rigid-оптимизация с одной костью;
- `>1` — skinned-путь; это значение также участвует в проверке пригодности для GPU-skinning.

Во всех 976 мешах с влияниями поле совпало с числом уникальных индексов костей в привязках. Это сильное эмпирическое подтверждение значения «число используемых костей», но исходное имя поля неизвестно, поэтому в описании сохранено нейтральное имя.

### Привязка вершины

```text
VertexAssignment:
    u8 bone_count
    repeat bone_count times:
        u16 bone_index
        float weight
```

Байт `influence_mode` читается в `0x100C31D4`; проверка нуля — `0x100C3203`. При ненулевом значении читается отдельный `bone_count` каждой вершины, даже если `influence_mode == 1`.

Диагностическая строка движка называет `influence_mode` числом bone influences. Во всех проверенных мешах с привязками он совпал с максимальным `bone_count` среди вершин. Значение `bone_count >= 10` отвергается движком в `0x100C32C4`.

## Объекты коллизии

Это блок, который в исходном пользовательском шаблоне назывался `ds2_skeleton`.

```text
CollisionObject:
    String name
    u8 type
    u16 bone_index             // FFFF: нет привязки к кости
    Matrix4 local_matrix
    параметры по type
```

| `type` | Примитив | Параметры после матрицы | Размер параметров, байт |
|---:|---|---|---:|
| `0` | Sphere | `float radius` | 4 |
| `1` | Box | `Float3 lengths`, полные длины сторон | 12 |
| `2` | Cylinder, не capsule | `float radius`, `float length` | 8 |
| `3` | Dummy / именованная трансформация | Нет | 0 |
| Другие значения | Семантика не установлена | Текущий reader также не читает параметры | 0 |

Стандартный reader — `0x100B6EA0`. Смысл типов подтверждён вызовами именованных импортов `ODE::Shape::AddSphere`, `AddBox`, `AddCylinder` в `gameres/executables/sv_game.dll:0x1007B404–0x1007B4A2`.

У коробки записаны полные размеры: вычисление её радиуса использует половину максимального размера. Dummy-объекты встречаются, например, под именами `#Dummy` и `#hinge`. Чтение даже одного лишнего `float` после dummy сдвигает весь остаток файла.

## Скелет

Reader — `0x100CD2C0`, вызывается через конструктор `0x100CE310`.

```text
Skeleton:
    u16 bone_count
    Bone bones[bone_count]
    u16 root_count
    u16 root_indices[root_count]
    u16 animation_count
    Animation animations[animation_count]
    u16 group_count
    AnimationGroup groups[group_count]
    u16 animation_slot_count
```

### Кость

```text
Bone:
    String name
    Matrix4 local_rest_matrix
    u16 parent_index           // FFFF: корень
    u16 child_count
    u16 child_indices[child_count]
    u16 animation_slot_index
```

Reader — `0x100CCD30`. Локальный характер rest-матрицы подтверждается вычислением накопленной трансформации через родителя в `0x100CB23F–0x100CB277`.

Последнее слово кости — индекс слота контроллера анимации, не material/shader slot. Оно попадает в поле объекта кости `+0xCE`. Код `0x100D9096–0x100D90A7` использует его для индексации массива указателей на контроллеры. Размер массива задаёт последнее `animation_slot_count` всего скелета.

## Анимации

### Заголовок и каналы

```text
Animation:
    String name
    float duration_seconds
    float time_parameter_seconds
    u16 channel_count
    AnimationChannel channels[channel_count]
    if model.version == "1.0":
        u16 event_count
        AnimationEvent events[event_count]

AnimationChannel:
    u16 bone_index
    String bone_name
    u32 key_count
    AnimationKey keys[key_count]
```

Reader анимации — `0x100D1370`. `duration_seconds` подтверждён потребителями длительности. Второй `float` точно является временным параметром: движок умножает его на 1000, как и длительность, при переводе в миллисекунды. Значение «интервал семплирования» — гипотеза, поэтому оно не закреплено в имени поля.

### Ключ: 45 байт

Reader — `0x100CF790–0x100CF8EE`.

| Смещение в ключе | Размер, байт | Поле |
|---:|---:|---|
| `+0` | 1 | `u8 flags` |
| `+1` | 16 | Quaternion `x, y, z, w`, четыре `float` |
| `+17` | 12 | `Float3 translation` |
| `+29` | 12 | `Float3 scale` |
| `+41` | 4 | `float time_seconds` |

Quaternion нормализуется при загрузке. Reader канала проверяет строгое возрастание времён ключей (`0x100D0FEF–0x100D1022`).

Между двумя различными ключами режим интерполяции определяется флагами правого, то есть следующего по времени, ключа:

| Маска | Поведение | Адрес потребителя |
|---:|---|---|
| `0x01` | Удерживать вращение левого ключа; иначе slerp | `0x100D2B4D` |
| `0x02` | Удерживать перенос левого ключа; иначе lerp | `0x100D2C8C` |
| `0x04` | Удерживать масштаб левого ключа; иначе lerp | `0x100D2D11` |
| `0x08` | Включить использование масштаба | `0x100D2CFA` |

Внутри интервала отключённый `0x08` правого ключа даёт единичный масштаб. При `0x08 | 0x04` удерживается масштаб слева, причём применение удержанного масштаба зависит от `0x08` левого ключа. В точный момент ключа используются его собственные значения и бит масштаба.

Матрица локальной анимационной позы имеет порядок `T * S * R` для векторов-столбцов: неравномерный масштаб умножает строки матрицы вращения. Это видно в `0x100D49B8–0x100D4AC5` и последующем умножении `0x100D4AC7` и далее. Обычное `T * R * S` здесь дало бы другой результат.

Старшие биты пока не расшифрованы. Они не меняют размер записи.

### События: различие 0.9 и 1.0

Проверка `strcmp(version, "1.0")` находится в `0x100D145D–0x100D1479`. В `0.9` нет ни массива событий, ни его счётчика; читать после каналов безусловный `u16` нельзя.

```text
AnimationEvent:
    float time_seconds
    String name
```

Запись события читается в `0x100D14B0–0x100D14EC`.

Пример реальных данных: в `gameres/models/actors/moto.ds2md`, анимация `walk`, счётчик событий расположен по `0x389AA`; записи содержат `(0.53333336, "step1")` и `(1.1333333, "step2")`.

### Группы контроллеров

```text
AnimationGroup:
    String name
    u16 bone_count
    u16 bone_indices[bone_count]
    u16 animation_slot_count
    u16 animation_slot_indices[animation_slot_count]
```

Reader — `0x100CD0E0–0x100CD1C2`. Вторая последовательность — индексы слотов контроллеров, а не ещё один список костей. Код `0x100D83F8–0x100D841D` присваивает контроллер группы каждому перечисленному слоту.

## Контрольный пример: svin.ds2md

Путь в установленной игре: `gameres/models/actors/svin.ds2md`. Версия `1.0`, имя модели `Object01`, материал `model_actor`. SHA-256: `f03993dac2ef8498032f270bfb9be01cd37c929430e7595679a2e5c0d0d24264`.

| Блок | Смещение от начала файла | Содержимое |
|---|---:|---|
| Начало меша, первая строка материала | `0x20` | Один меш |
| Заголовок меша | `0x84` | AABB; 670 примитивов; list; `skinning_count = 2` |
| Счётчик индексов | `0xA5` | 2010 |
| Индексы | `0xA9` | `u16[2010]` |
| Счётчик вершин | `0x105D` | 599 |
| Позиции | `0x105F` | `Float3[599]` |
| Нормали | `0x2C73` | `Float3[599]` |
| UV | `0x4887` | `Float2[599]` |
| `influence_mode` | `0x5B3F` | 2 |
| Конец меша / счётчик коллизий | `0x6BE3` | Одна коллизия |
| Коллизия | `0x6BE4` | `#Box02`, box, привязка к кости 0 |
| `has_skeleton` | `0x6C3B` | 1 |
| Начало скелета / счётчик костей | `0x6C3C` | Две кости |
| Счётчик анимаций | `0x6CE0` | Шесть анимаций |
| Первая анимация | `0x6CE2` | `run` |
| Счётчик групп | `0x8C08` | Три группы |

В привязках 588 вершин имеют одно влияние, 11 — два. Кости: `Bone01` — корень; `Bone02` — его ребёнок. Обе используют слот контроллера 0. Анимации: `run`, `jamp1`, `jamp2`, `jamp3`, `jamp4`, `idle`; написание `jamp` взято из файла. Группы `entry_model`, `upper_model`, `nogi` содержат кости `[0, 1]` и слоты `[0]`.

Границы записанных позиций не совпадают с AABB меша. После применения восстановленной цепочки `animated_global * inverse(global_bind)` к `run` при `t=0` границы совпадают с AABB с погрешностью порядка `1e-5`. Записанные позиции нельзя просто домножать на локальные матрицы костей.

## Проверка на корпусе

В корпусе `gameres/models/**/*.ds2md` 1290 файлов четырёх версий: `0.9`, `1.0`, `0.6`, `0.5`. Все файлы прочитаны до точного EOF.

| Представление и версия | Число файлов | Результат |
|---|---:|---|
| Бинарный `0.9` | 970 | Разбор до точного EOF |
| Бинарный `1.0` | 297 | Разбор до точного EOF |
| Бинарный `0.6` | 5 | Разбор до точного EOF |
| Текстовый `0.5` | 18 | Разбор до точного EOF |

В современной части (`0.9`/`1.0`): 2097 мешей, из них 26 strips; 2455198 вершин; 5124353 индекса; 9101 запись кости; 2703 анимации; 3346003 ключа. В 15 анимациях обнаружено 29 событий. Числа относятся к записям в файлах, а не к уникальным игровым сущностям; старые матричные отсчёты считаются одной анимацией на модель.

Проверены границы чтения, индексы вершин и точное совпадение финального смещения с размером файла. Отдельно проверены индексы родителей, детей, корней, костей каналов, костей групп и слотов контроллеров; нарушений не найдено. Точный EOF и корректные ссылки подтверждают разметку, но сами по себе не доказывают все смысловые названия полей.

## Текстурные ссылки в корпусе

В первом текстурном слоте 2097 мешей версий `0.9`/`1.0`: 689 пустых ссылок, 73 `$missing$`, 7 путей `.tga` и 1328 путей `.dds`. Всего встречается 678 различных непустых строк.

Все записанные пути `.tga` существуют. Для 422 ссылок `.dds` найдены локальные файлы; ещё 26 используют старые абсолютные или относительные пути, среди них `Y:\GAMERES\ANIMALS\RAT.DDS`, `KUST_1.DDS`, `PLECH1.DDS`. Ни одно имя `.dds` не начинается с `gameres`: локальные копии обычно находятся рядом с моделью.

Qt-viewer также читает `diffuse_texture_transform` по имени материала из общего `.mat` parser; остальные свойства model appearance этим не меняются. Семантика scroll/rotate, источник времени и ограничение GLB описаны в [разделе материалов DS2](ds2.md#diffuse_texture_transform).

## Что остаётся неустановленным

- Назначение нулевых/непрозрачных полей текстового `0.5` и бинарного `0.6`, отсутствующие в корпусе ветки, точный смысл временных параметров, их загрузчики и конвертеры. Наблюдаемый порядок данных всех 23 файлов восстановлен выше.
- Точное назначение второго временного параметра анимации.
- Старшие биты флагов ключа.
- Точная связь `primitive_count` и количества индексов у strips.

Ни одно из этих неизвестных полей не мешает установленной разметке стандартных бинарных моделей исследованного корпуса.
