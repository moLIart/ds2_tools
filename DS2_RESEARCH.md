# You Are Empty: геометрия уровней DS2

## Результат и границы

Разобран `DS2GeometryFile_1`, версия `0.8`: все 17 файлов из `gameres/maps/map00`…`map16`, суммарно 697832959 байт и 65606 описаний мешей. Проверочный парсер последовательно доходит до EOF каждого файла, включая служебные секции. Геометрия, оба UV-набора, материалы, атласы освещения, матрицы объектов и отдельные потоки цвета инстансов доступны просмотрщику.

Артефакты:

- `inspect_ds2.py` — информация в JSON, границы секций, материалы, счётчики и смещения массивов; стандартная библиотека Python.
- `ds2_scene.py` — независимая Python-реализация загрузки сцены для исследования формата.
- `viewer/map_loader.cpp`, `viewer/render_widget.cpp` — нативный Qt6/QRhi-просмотрщик `ds2_view`: альбедо, лайтмапы, вершинное освещение и frustum culling через `vistree`.
- `test_ds2.py` — изолированные проверки Python-парсера и материалов, без ресурсов игры.
- `viewer/camera.h` — общая Z-up камера, орбита, полёт, clipping и конечная дальность.
- [VISTREE_RESEARCH.md](VISTREE_RESEARCH.md) — подробный разбор октодерева: дисковый формат, runtime-связи, адреса DLL, корпус карт и установленные ограничения.

Это **не** полная эмуляция движка. Не воспроизводятся отражения/cubemap, bump/specular, преломление воды, flare, анимация/преобразования UV, динамическое освещение от игровых источников, туман, postprocessing, небо и игровые объекты из сценариев. Специальные материалы показывают только доступную статическую составляющую, с предупреждением; это не заявляется их игровым видом. Коллизии `.ds2cm`/`.ds2cm2` и навигация `.ds2aim` не исследовались. Исходные ресурсы, DLL и базы IDA не изменялись.

## Запуск

Из каталога игры:

```powershell
pwsh -File ds2_research/build.ps1
python ds2_research/inspect_ds2.py gameres/maps
python ds2_research/inspect_ds2.py gameres/maps/map01/gor.ds2 --meshes
.\ds2_research\build\ds2_view.exe gameres/maps/map01/gor.ds2
```

Сборка требует Qt 6.11 с Widgets, GuiPrivate и ShaderTools, CMake, Ninja и совместимый MSVC x64. `build.ps1` использует `vsenv`, если компилятор ещё не активирован, и по умолчанию берёт Qt из `C:/Qt/6.11.0/msvc2022_64`. Другой путь задаётся параметром `-QtRoot`. Оба EXE и необходимые Qt DLL/plugins размещаются в `ds2_research/build`. Python для запуска просмотрщиков не нужен. QRhi по умолчанию использует Direct3D 11 в Windows; карте нужны D32F и 4× MSAA. QRhi зависит от приватного API Qt, поэтому DLL должны соответствовать версии Qt, с которой собран EXE.

Установка обоих просмотрщиков с Qt runtime в отдельный каталог:

```powershell
pwsh -File ds2_research/install.ps1
```

`install.ps1` вызывает `cmake --install` с конфигурацией Release и префиксом `ds2_research/install`. Путь не привязан к текущему рабочему каталогу: оба каталога вычисляются от расположения скрипта. Другой каталог установки задаётся параметром `-Prefix`. После обновления `CMakeLists.txt` повторно сконфигурируйте каталог сборки, чтобы обновить install-скрипты.

Если сборка выполнялась с `-BuildDirectory`, передайте тот же путь `install.ps1 -BuildDirectory`. EXE, необходимые Qt DLL и `qt.conf` устанавливаются в `bin`, плагины Qt (включая `platforms/qwindows.dll`) — в `plugins`. В Windows зависимости автоматически собирает `windeployqt`; переводы Qt и программный OpenGL не копируются, как и при обычной сборке. Игровые ресурсы в установку не входят; при запуске из другого каталога используйте `--game-root`.

Без аргумента просмотрщик открывает первую установленную карту. Карта выбирается напрямую из выпадающего списка `Map` на панели инструментов; пункты содержат пути относительно `gameres/maps`. `Open...` и перетаскивание `.ds2` также обновляют выбранный пункт, а карта вне каталога добавляется в список. При неудачном открытии сохраняются предыдущая сцена и выбранная карта.

`--debug-rhi` включает debug/validation layer графического API. `--game-root <каталог>` явно задаёт каталог с `gameres`; без него просмотрщик ищет ресурсы рядом с открываемым файлом, рабочим каталогом и EXE.

Оба просмотрщика используют встроенный стиль Qt Widgets `Fusion`, заданный при запуске до создания окон.

Окно состоит из обычного Qt toolbar, отдельного QRhiWidget и строки состояния. В строке состояния находятся FPS, режим камеры, скорость и число отобранных мешей; полный путь, заметки и предупреждения доступны в подсказке. VSync включён в обоих просмотрщиках: до создания окон задан `swapInterval=1`. Скорость движения зависит от `dt`, а не от FPS. Кнопка `Controls` показывает сочетания клавиш.

| Действие | Управление |
|---|---|
| Совместный режим / альбедо / лайтмапа / цвет вершин / уникальные цвета мешей | `1` / `2` / `3` / `4` / `5` |
| Орбита | ЛКМ + перемещение; горизонтальное вращение без инверсии |
| Панорамирование | СКМ + перемещение |
| Приближение | Колесо |
| Полёт / орбита | `F`; ПКМ включает полёт и поворачивает взгляд |
| Перемещение в полёте | `W/S` вперёд/назад, `A/D` влево/вправо относительно взгляда, `Q/E` вниз/вверх, Shift ускоряет |
| Скорость полёта | Колесо в режиме полёта |
| Дальность прорисовки | PageUp умножает предел на 1.25, PageDown делит на 1.25; End возвращает Auto |
| Вписать всю карту / каркас | Home / `G` |
| Показ источников света | `L` или действие `Lights` на панели |
| Открыть файл | Ctrl+O |
| Выбор карты | Выпадающий список `Map` на панели инструментов |

Удержание ЛКМ/СКМ/ПКМ в области карты скрывает и захватывает курсор; поворот использует относительное движение мыши и не упирается в край окна. Курсор возвращается после отпускания всех удерживаемых кнопок, при потере фокуса, открытии диалога или закрытии просмотрщика. Нажатия кнопок интерфейса курсор не скрывают. В полёте мышь влево поворачивает взгляд влево; знак орбитального перетаскивания сохранён отдельно.

В Windows нативное окно области карты подготавливается до первого нажатия мыши, чтобы HWND не менялся после `grabMouse()`. Состояние захвата хранится отдельно от нажатых кнопок; отпускание последней кнопки, потеря захвата ОС и смена HWND снимают ограничение курсора и возвращают его видимость.

Камера использует Z-up. Home консервативно вписывает полный AABB, поэтому вытянутые карты сначала выглядят небольшими. Режим лайтмапы показывает исходный атлас без усиления 2x; поверхности без применяемой лайтмапы серые. Режим цвета вершин аналогично показывает доступный поток цвета. Пурпурный цвет обозначает отсутствующую/не декодированную текстуру, сообщение содержит исходную ссылку.

Режим Mesh colors (`5`, для запуска — `--mode meshes`) окрашивает каждый меш в отдельный плоский цвет. RGB24-цвет вычисляется один раз из нулевого индекса записи `meshes`, а не из материала или VAO: экземпляры с общей геометрией различаются, цвет сохраняется при движении камеры, отсечении и перезагрузке той же карты. Отображение индексов в RGB24 не имеет повторов для первых `2^24` мешей. Текстуры, освещение, alpha test и blending на окраску не влияют; даже прозрачные эффекты показываются сплошной геометрией с проверкой и записью глубины. Материальное отсечение обратных граней сохраняется. Клавиша `1` возвращает обычный совместный режим.

Глубина карты рассчитывается по фактическому направлению взгляда, а не по оставшейся от орбиты точке target. Внутри AABB ближняя плоскость остаётся на 0.5 единицы игры; она не отодвигается на процент расстояния до центра карты. Вне AABB она поджимается к границе карты для сохранения точности depth buffer. В режиме Auto дальняя плоскость охватывает AABB по текущему взгляду, в том числе после пролёта через старый target.

Карта рисуется в отдельный QRhi render target с глубиной D32F и reversed-Z: near → 1, конечный far → 0, очистка глубины в 0, сравнение Greater. `QRhi::clipSpaceCorrMatrix()` переводит проекцию в clip-конвенцию текущего API. Та же zero-to-one проекция используется для CPU frustum culling.

Цвет RGBA8 и глубина D32F используют 4× MSAA. QRhi разрешает цвет в односэмпловую текстуру QRhiWidget, которую Qt компонует с toolbar и строкой состояния. Render target переразмеряется вместе с областью рисования; при отсутствии D32F или четырёх сэмплов выводится ошибка. Alpha-to-coverage не включён.

Для `depth_offset=true` сохраняется положительный bias при обратной глубине: QRhi depth bias и slope-scaled bias равны 1. Reversed-Z повышает точность вдали, но не задаёт порядок для совпадающих полигонов и не исправляет реальные пересечения.

Регулируемая дальность ограничивает глубину вдоль взгляда в единицах игры, а не расстояние до центра меша. По умолчанию включён Auto; первое нажатие PageUp/PageDown берёт текущую автоматическую дальнюю плоскость. Предел 1…100000000 отображается в toolbar и сохраняется при движении, Home/Fit и переключении карт; End сбрасывает его в Auto. Если карта ближе, автоматическая подгонка может уменьшить фактическую дальнюю плоскость. Если вся карта дальше предела, она не рисуется, а near поджимается до корректной проекции. Предел применяется и к GPU clipping, и к `vistree`.

Frustum culling включён постоянно: шесть плоскостей извлекаются из той же матрицы `projection @ view`, которая передаётся шейдеру, с учётом `0 <= z_clip <= w_clip`. Обход `vistree` начинается с узла 0, отсекает AABB ячеек вне frustum и собирает уникальные mesh IDs из пересекающихся листьев. Затем проверяются собственные мировые AABB мешей: лист лишь пересекает меш, а не обязательно охватывает его. Границы считаются включёнными с допуском на f32. Матрица инстанса к уже мировому AABB повторно не применяется.

После frustum culling непрозрачные меши сортируются от ближних к дальним по квадрату расстояния от камеры до центра мирового AABB. Это даёт ближним поверхностям возможность раньше заполнить depth buffer; группировка по имени материала и VB используется только при равном расстоянии. Прозрачные меши рисуются после непрозрачных, от дальних к ближним. В обеих очередях первичен явный приоритет материала `sort_value`, а порядок по расстоянию пересчитывается при каждой отрисовке по текущему положению камеры.

При отсутствии или пустом `vistree` проверяются AABB всех мешей. Счётчик `N/M visible` показывает число отобранных мешей, не число реально видимых поверхностей: геометрия за стенами этим способом не скрывается.

GPU-запросы окклюзии и conditional rendering в просмотрщике не используются. Остаются frustum culling через `vistree` и обычная проверка глубины; исследование областей окклюзии оригинального движка не относится к этому пути.

Сохранение кадра с выходом, включая ненулевой код при ошибке загрузки:

```powershell
.\ds2_research\build\ds2_view.exe gameres/maps/map01/gor.ds2 --mode lightmap --screenshot gor-lightmap.png
```

## Базовые типы и секции

Little-endian, плотная упаковка без padding. `f32` — IEEE 754. `String = u16 byte_length + byte[byte_length]`, без NUL. CP1251 используется инструментом для отображения непомеченных строк.

```text
String "DS2GeometryFile_1"
String "0.8"
repeat to EOF:
    String "DS2Chunk_begin"
    String chunk_name
    payload
    String "DS2Chunk_end"
```

У секции **нет длины в байтах**. Поиск маркера внутри бинарного payload не является корректным общим способом пропуска неизвестной секции. Парсер читает известные записи последовательно и отвергает неизвестные секции/версии, обрезанные данные и лишние байты. В файлах встречаются `meshes`, `buffers`, `lightmaps`, `vistree`, необязательная `lights`, `models`.

Оригинальный загрузчик проверяет версию численно как 0.8, а завершающий маркер потребляет внешним циклом без отдельной проверки. Исследовательский парсер намеренно строже: принимает строку `0.8` и проверяет каждый `DS2Chunk_end`.

## Меши

`meshes = u32 count + Mesh[count]`. Начало записи:

```text
u8 instanced
String material
String diffuse
String bump
String luminosity
String reflection
String specular
```

Далее смещения относительно конца шестой строки (`S`):

| Смещение | Тип | Назначение |
|---|---|---|
| `S+0` | Float3 | AABB min |
| `S+12` | Float3 | AABB max |
| `S+24` | Float3 | Центр сферы |
| `S+36` | f32 | Радиус сферы |
| `S+40` | 156 байт | Дополнительный bounds-блок; reader читает 12+12+36+96 байт |
| `S+196` | u8 | Флаг в памяти `+0x114`, точная семантика не установлена |
| `S+197` | Float3 | Вектор в памяти `+0x118`, точная семантика не установлена |
| `S+209` | u32 | Индекс лайтмапы, `FFFFFFFF` в корпусе означает отсутствие |
| `S+213` | u32 | Число примитивов |
| `S+217` | u32 | Число вершин меша |
| `S+221` | u32 | Поле памяти `+0xD8`, точная семантика не установлена |
| `S+225` | u32 | Число индексов triangle list |
| `S+229` | u32 | ID индексного буфера list |
| `S+233` | u32 | Начальный индекс list, в элементах |
| `S+237` | u32 | Число индексов triangle strip |
| `S+241` | u32 | ID индексного буфера strip |
| `S+245` | u32 | Начальный индекс strip, в элементах |
| `S+249` | u32 | ID буфера вершин |
| `S+253` | u32 | База вершин в буфере |

Фиксированный хвост — 257 байт. В движке индекс лайтмапы и три следующих поля сохраняются младшими 16 битами; сырые u32 остаются в отчёте `raw_draw_fields`.

List и strip — **два независимых диапазона**, а не переключатель топологии или LOD. `0x10057F80` рисует оба ненулевых диапазона. ID/начало пустого диапазона могут быть `FFFFFFFF`; их нельзя безусловно разыменовывать. Индекс обращается к `VB[vertex_start + index]`: у обычных world-мешей база часто нулевая, а индексы охватывают общий VB, не только `vertex_count` данного меша.

Если `instanced != 0`, после `S+257` следуют ещё 80 байт:

```text
u32 color_buffer_id
u32 color_vertex_start
f32 matrix[16]
u32 model_group_reference
u32 model_instance_reference
```

Это отдельный поток запечённого RGBA для экземпляра, не дополнительная геометрия. Матрица хранится row-major, translation в элементах 3, 7, 11. Reader транспонирует её, а `0x100446F0` через IAT `0x1017F308` вызывает `OPENGL32!glMultMatrixf`.

Каждая такая запись рисуется **один раз со своей матрицей**. Повторное размножение по секции `models` создаёт дубликаты. Ссылки на группы/экземпляры полезны как метаданные, но не годятся для строгой проверки связи: в корпусе есть расхождения матриц и выходы этих advisory-ссылок за число экземпляров. Авторитетна матрица самого меша.

## Общие буферы

`buffers = u32 count + Buffer[count]`. Счётчик общий для VB, IB и отдельных цветовых буферов.

```text
u32 flags
u32 count
if flags & 1:
    u32 indices[count]
else:
    optional attribute arrays in the order below
```

| Бит | Массив | Байт на элемент |
|---|---|---|
| `0x02` | Float3 positions | 12 |
| `0x08` | Float2 albedo UV | 8 |
| `0x10` | Float2 lightmap UV | 8 |
| `0x20` | u32 RGBA[4] | 16 |
| `0x04` | Float3 normals | 12 |
| `0x40` | Float3 tangents | 12 |
| `0x80` | Float3 binormals | 12 |

Это SoA, **не interleaved**. Порядок не совпадает с сортировкой битов. `0x1A` означает позиции + два UV-набора. Цвет на диске — четыре u32 на вершину; движок использует младший байт каждого канала и получает RGBA8. Индексы на диске u32, хотя движок преобразует их в u16.

Нативный загрузчик готовит interleaved-вершины и u32-индексы для QRhi. Одинаковая комбинация `(vertex_buffer, vertex_start, color_buffer, color_start)` разделяет один диапазон вершин между мешами; отдельные потоки цвета получают собственную привязку. Матрицы экземпляров остаются отдельными и применяются GPU, без размножения мировой геометрии. Triangle strips преобразуются в списки с сохранением чётности.

Геометрия загружается в immutable vertex/index buffers, параметры материалов — в выровненный uniform buffer. Draw calls используют готовые shader bindings и кэшированные pipeline states. После culling расстояние до центра каждого кандидата вычисляется один раз для сортировки кадра; рабочие массивы переиспользуются.

Смена сцены подготавливает новые CPU/GPU-ресурсы до замены текущих. При ошибке чтения или выделения ресурсов предыдущая карта сохраняется. Отсутствующие UV равны нулю, отсутствующий цвет — белый.

Некоторые нормали/тангенты поставляемых файлов содержат NaN; этот просмотрщик их не использует. В UV встречаются очень большие **конечные** значения, поэтому позиционное ограничение камеры к UV неприменимо. Неконечные используемые координаты и опасные позиции отвергаются, а не молча заменяются нулями.

## Лайтмапы и альбедо

`lightmaps = u32 count + String[count]`. Порядок списка задаёт нулевые индексы атласов. Например, `lastzlo\\lastzlo_lm_0` указывает на соседний `lastzlo_lm_0.tga`. Имена нельзя синтезировать из номера материала или числа лежащих рядом изображений.

Всего рядом с картами 35 TGA, но `.ds2` ссылаются только на 32. Неиспользуемые этим набором геометрии: `map05/kolhoz_lm_2.tga`, `map07/lastlevel_lm_3.tga`, `map09/meat_lm_1.tga`.

Ссылки diffuse часто содержат старые пути `D:\\quake`, `Z:\\gameres` или UNC разработчиков. Просмотрщик не обращается к этим дискам/сетевым адресам: сначала ищет соседнее DDS/TGA, затем локальный `gameres/textures`, предпочитая DDS. Неоднозначность не разрешается выбором первого попавшегося файла. Все 60 встреченных имён материалов имеют декларации в `gameres/materials/*.mat`.

DDS сохраняет исходную V; TGA декодируется в нижнее начало и компенсируется шейдером через `1-V`. Инверсия независима для альбедо и лайтмапы. Все 35 соседних lightmap TGA имеют descriptor 0 (bottom-origin).

`viewer/texture.cpp` читает DXT1/DXT3/DXT5 и TGA, включая RLE. При поддержке BC готовые DDS mip-уровни загружаются без декомпрессии; иначе декодируются в RGBA8. Шейдер ограничивает LOD последним сохранённым DDS-уровнем, в том числе при неполной цепочке. Для TGA mip-уровни генерирует QRhi. Padding между UV-островами лайтмапы не добавляется.

Фильтрация линейная с трилинейным выбором mip-уровней. В QRhiSampler нет настройки анизотропии, поэтому fragment shader берёт до 16 выборок вдоль длинной оси пиксельного следа текстуры. Это собственная аппроксимация анизотропной фильтрации, а не настройка аппаратного sampler.

Повторение/ограничение координат задают кэшированные QRhi samplers repeat/clamp. Текстуры, bindings и pipeline states принадлежат сцене; Qt рисует интерфейс отдельно.

## Статическое освещение и материалы

Обычные fixed-function пути подтверждены дизассемблированием, а не только Cg-шейдерами:

- LM: `RGB = 2 * albedo * lightmap`, дополнительно умножение на vertex RGB при `use_vertex_colors`.
- VX: `RGB = albedo * vertex RGB * (2 if overbright else 1)`; `overbright` по умолчанию включён.
- Self-illumination: `RGB = albedo * constant color`, без усиления; `def_selfilum_50` даёт `0.5 * albedo`.
- Усиление 2 относится только к RGB, не alpha.

LM использует texenv mode 7 → `0x10044FA2`, `GL_COMBINE/MODULATE`, `GL_RGB_SCALE=2` в `0x1004500E`. VX mode 9 → `0x10045120`, TEXTURE × PRIMARY_COLOR с усилением 2. Self-illumination выбирает mode 0; `0x10044260` задаёт белый RGBA, если нет явного color3.

Разбираются runtime-поля `blend`, `alphatest { greater threshold }`, `depth_write`, `depth_test`, `depth_offset`, `cull_face`, `sort_value`, `color3`, `diffuse_texture`, `clampmap`, `self_illumination`, `use_vertex_colors`, `overbright`. `material_type opaque` не запрещает явный blend; `ds2compiler transparent` сам по себе **не** включает runtime-прозрачность. Наличие alpha в DDS также не включает blending автоматически. `fallback_material` — аппаратный fallback, не наследование.

В `.mat` встречаются вложенные блоки, `//`, `/* … */` и незакрытый block-comment до EOF в `ds2_man.mat`; закомментированная декларация не должна переопределять рабочую. Подстановки `$diffuse$`, `$white$`, `$black$` обрабатываются отдельно от имён файлов. У материала без diffuse-слота не подставляется произвольно diffuse из меша.

## Служебные секции

Все секции начинаются с u32 count:

- `vistree`: разреженное октодерево. Запись содержит Float3 min/max, **f32 радиус сферы** (`sphere_radius`), Float3 центр (`sphere_center`) и u8 leaf; лист — список индексов мешей с пересекающимися AABB, внутренний узел — восемь child IDs с `FFFFFFFF` для отсутствующих детей. Парсер проверяет ссылки, границы, топологию дерева и наличие всех мешей в листьях. Полная структура, обработка индексов движком и отдельная окклюзия описаны в [VISTREE_RESEARCH.md](VISTREE_RESEARCH.md); это не PVS.
- `lights`: 72 байта на запись; типы, основные поля и неустановленные параметры описаны ниже. Просмотрщик показывает позиции источников гизмо, но не применяет их к освещению.
- `models`: String name, Float3 min/max, u32 instanceCount; экземпляр = Matrix4 + Float3 min/max, 88 байт на диске. Размер структуры в памяти 100 байт переносить на файл нельзя.

### Chunk `lights`

Формат записи: `u32 type + три Float3 + восемь 32-битных параметров`. Типы подтверждены передачей записи в OpenGL по `0x10044800`: `1` — point, `2` — directional, `3` — spot. Загрузчик `0x10057540` преобразует их во внутренние значения `1`, `0`, `2` соответственно.

| Смещение | Семантика и статус |
|---:|---|
| `+0x00` | `u32 type`: `1` point, `2` directional, `3` spot. |
| `+0x04` | Float3 position. |
| `+0x10` | Float3 direction; у point не используется. |
| `+0x1C` | Float3 diffuse color. |
| `+0x28` | Range: ограничивает AABB источника и расстояние при запросе освещения. |
| `+0x2C` | **Не установлено.** |
| `+0x30` | **Не установлено.** У всех point/spot проверенного корпуса значение совпадает с range, но это не раскрывает назначение поля. |
| `+0x34` | **Не установлено.** Потребитель не подтверждён; присваивать этому полю inner spot angle по одним значениям корпуса нельзя. |
| `+0x38` | Outer spot angle в градусах. OpenGL получает `GL_SPOT_CUTOFF = angle / 2`; запрос освещения принимает угол не больше `(angle + 1) / 2`. |
| `+0x3C` | **Не установлено.** |
| `+0x40` | Читается как bool; назначение **не установлено**. |
| `+0x44` | Читается как bool; назначение **не установлено**. |

Статус **«не установлено»** означает отсутствие подтверждённой семантики в исследованных путях, а не отсутствие потребителей в других частях движка. Cg-шейдеры, скриптовые интерфейсы и все остальные читатели записей не проверены исчерпывающе.

Directional lights попадают в отдельный глобальный список. Point и spot связываются с листьями `vistree` по AABB `position ± range` (`0x10056B80`, `0x10056F90`). Запрос `0x1004A660` проверяет `distance < range`, cone у spot и отсутствие перекрытия collision-ray. OpenGL-uploader `0x10044800` подтверждает position, direction, diffuse color и outer spot angle; остальные параметры этот путь не раскрывает.

В проверенных 17 картах 746 записей: 422 point, 323 spot и одна directional. Направления directional/spot нормализованы, range положительный.

`ds2_view` показывает point как сферу, а spot и directional как конус. Центр сферы и вершина конуса совпадают с position; конус направлен по direction. Радиус сферы и длина конуса равны range, радиус основания конуса — `0.3 * range`; outer spot angle не используется. Гизмо используют diffuse color с alpha `0.35`, проверяют глубину карты, не записывают собственную глубину и сортируются от дальних к ближним. Поверх полупрозрачной геометрии рисуется её каркас, а position дополнительно отмечается трёхосным перекрестием с длиной оси `0.2 * range`. Рядом со счётчиком мешей статусная строка показывает общее число источников и отдельно point, spot и directional.
